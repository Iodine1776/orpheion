# What counts as one request?  
**Orpheion**

**Rule of thumb:** If you can demo it clearly in a **single Loom** as one coherent deliverable, it’s one request. If not, split it—or use a Kickoff Sprint.

You can keep many items in the **backlog**. Only **one** is active at a time.

---

## Yes — typically one request

| Example | Notes |
| --- | --- |
| One marketing / landing page from locked Figma | Standard size |
| Up to ~3 related sections on an existing page | e.g. hero + features + CTA |
| One component set in one context | Pricing cards, FAQ, nav + mobile menu |
| A defined polish / bugfix listed up front | e.g. 5–10 specific UI fixes |
| One CRO variant of an existing section | A/B from provided designs |
| Wire one form to a named SaaS destination | HubSpot, Resend, etc. |
| Responsive fixes for one page | Against provided breakpoints |
| Final copy/asset swap with no redesign | Text/images only |

---

## No — split, sprint, or change order

| Example | Why |
| --- | --- |
| Full 5-page marketing site as “one request” | Kickoff Sprint or sequenced requests |
| Dashboard / authenticated app UI | Out of standard frontend queue |
| “Improve the design” / exploration | Not a production subscription |
| “Build the website” with no locked file | Missing required input |
| Several pages in parallel as one request | One active deliverable only |
| Custom auth, CMS architecture, complex backend | Change order or different offer |
| Unlimited revisions after design lock | Queue the next request instead |
| Same-day rush | Only with a paid rush add-on |
| Strategy, copywriting, SEO programs | Not included |

---

## Edge cases

- **“Make the whole site match the new brand kit”** → Split by page/section; each is a request.  
- **“Add animations everywhere”** → One page/section of specified motion = one request; sitewide = multiple.  
- **Mid-flight redesign** → Restarts the active request unless the change is trivial (copy/image swap).  
- **Unsure?** Put it on the board before it goes active—Orpheion will confirm yes/no async.
